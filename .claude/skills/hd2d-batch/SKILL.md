# HD-2D daily sprite batch

Turns the next N creatures in the sprite queue into in-game sprites: Codex generates, you review, normalize, add to the manifest and check them on stage. Daily image quota is the limit, so spend it carefully. Method and rules: `docs/HD2D.md`; prompts: `docs/hd2d/prompts.md` (generated by `scripts/hd2d-prompts.py`, never edited by hand).

`N` = the argument, default **4**. Budget = **N + 2** Codex generations in total, so a couple of rejects can be retried.

## 1. Preflight

```bash
python3 scripts/hd2d-codex.py check
python3 scripts/hd2d-codex.py queue
```

- `check` exit 1 means Codex isn't offering its image tool. That happens when the account's image quota (shared with ChatGPT) is used up. **Stop**, tell the user to retry after the reset, and generate nothing.
- `queue` lists species without a sprite, in order. Part A creatures (Brinecrab, Puddlet, Brambat) also make a body-type anchor. Take the first N.
- If an earlier Codex image for a queued species is already in `docs/hd2d/original/` (`<key>-codex-*.png`) and was never normalized, review that before generating again.

## 2. Generate and review, one creature at a time

```bash
python3 scripts/hd2d-codex.py gen <key>      # fresh Codex session -> docs/hd2d/original/<key>-codex-N.png (takes 1–4 min)
```

Each `gen` is a new Codex session (one chat per character) with the right anchor attached. Run them one after another, not in parallel. Then **Read the saved image** and judge it against the checklist in `docs/HD2D.md` plus:
- It matches its SUBJECT in `docs/hd2d/prompts.md` (silhouette hook, features, colours, body plan).
- It is one creature facing right, whole body in frame, on a flat magenta background (keyed out later), with no floor, shadow, glow or text.
- It looks like pixel art on a visible grid, not a painting.

If it fails, `gen` again (it numbers the files `-codex-2`, `-codex-3`). Retry at most **twice per creature**. If the third try still fails, skip the creature and report why. Don't edit prompts in a batch; suggest design changes to the user instead.

If `gen` prints `no image produced` and the last output says the tool is unavailable, the quota ran out mid-batch: stop, and finish the review and wiring steps for what you already have.

## 3. Normalize

For each approved image, using `size` from `queue`:

```bash
python3 scripts/hd2d-sprite.py docs/hd2d/original/<key>-codex-N.png godot/art/hd2d/<key>.png --kind monster --size <size> --scale 1
# Part A creatures only, also the anchor:
python3 scripts/hd2d-sprite.py docs/hd2d/original/<key>-codex-N.png docs/hd2d/anchors/<plan>.png --kind monster --size <size>
```

- The reported **source grid should be about 7–12 px**. Far outside that means the pixels will look a different size from the cast: reject the image (back to step 2).
- Read the output. A pink or magenta fringe left from the background means the key was too tight: rerun with `--tol 48`.
- Keep the printed `anchor`, `height` and `head`.

## 4. Wire into the game

In `godot/art/hd2d/manifest.gd` `creatures()`, replace the species' placeholder (`fox()`, `sable()`, `dragon(...)`) with:

```gdscript
"<key>": painted("<key>", Vector2(<ax>, <ay>), <height>, Vector2(<hx>, <hy>)),
```

- `ay` and `height` as printed. Set `ax` to the **body's horizontal centre**, not the printed value: the normalizer takes the centre of the lowest pixel row, which lands on a claw or tail tip for many creatures. Judge it from the image (fraction of the width).
- `head` (the projectile target) should sit on the face or upper body, as a fraction of the image.
- Special cases (from the notes in `prompts.md`):
  - `warden`: `painted(...)` as usual, which drops its old ramps and wash.
  - `noctyrm`: it must stay recoloured per element, so use `painted(...)` and then set `"recolor": {}` on the result (e.g. `painted(...).merged({"recolor": {}}, true)`), without the night wash.

Then:

```bash
godot --headless --audio-driver Dummy --path godot --import          # writes the .import files for the new PNGs
godot --headless --audio-driver Dummy --path godot --quit            # load check: no script errors
godot --headless --audio-driver Dummy --path godot --script res://tests/test_core.gd
godot --audio-driver Dummy --path godot --resolution 390x844 res://tests/stage_preview.tscn -- --out=<scratch>/<key> --pair=<key>,<other>
```

The `--pair` run puts `<key>` on the enemy pedestal (mirrored, facing left) and `<other>` on yours. Pair two new sprites at a time, then swap them, so each one is seen on both sides. Read `<scratch>/<key>/stage_b0_idle.png` and check: feet on the pedestal, the body centred on it, a sensible size next to its partner, nothing clipped badly. Adjust `ax`/`ay` or `head` and rerun if needed.

## 5. Record and report

- In `CLAUDE.md` §13 "Current art", say which species now have real sprites and which are still placeholders.
- When an anchor was made (Part A), add its row to the anchor table in `docs/HD2D.md` Step 1 (drop "(to make)").
- Don't commit unless the user asks.
- Report: the creatures done (with the stage preview images), any skipped and why, Codex generations used out of the budget, and what `queue` will start with tomorrow.
